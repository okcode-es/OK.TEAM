# okTeam UI Craft Specification (v2 — Personio Layout + okTeam Light Enterprise Palette)

面向西班牙华人企业主、店长与员工的极简中文体验 + 100% 西班牙劳动法合规输出。采用 **Personio 级企业布局架构与高密度信息排布**，搭配 **okTeam 专业浅色企业风配色体系**，追求高对比度、层次清晰、零暗黑沉重感、零装饰噪音的生产力工具质感。

## 1. 视觉系统红线（严禁暗黑背景与浅蓝侧栏）
- **左侧可折叠导航栏**：深海夜蓝 **`#0B1120`**（`bg-slate-950`），高对比度柔白图标与文字（`text-slate-300` / `hover:text-white`），激活态采用**企业钴蓝胶囊高亮**（`bg-[#2563EB] text-white` 或 `bg-blue-600 text-white`）；支持展开（图标+文字）与收起（极简图标列）；左下角固定帮助入口、个人头像与一键快捷打卡按钮（`▶`）。
- **主工作区画布与卡片层级**：
  - 页面底色固定柔冷浅灰 **`#F3F5F9`**（`bg-[#F3F5F9]`）。
  - 主工作区卡片使用纯白圆角卡：**`bg-white rounded-xl border border-slate-200/75 shadow-[0_1px_2px_rgba(15,23,42,0.04)]`**。
- **品牌主色与语义色**：
  - 品牌主色：**企业钴蓝 `#2563EB`（`blue-600` / hover `blue-700`）**，用于主操作按钮、活跃 Tab 下划线、链接、环形/线性进度条、日历“今天”高亮竖线与焦点环。
  - 业务状态严格采用低饱和胶囊：
    - 成功 / 在职 / 已批准：`text-emerald-700 bg-emerald-50 border-emerald-200`
    - 信息 / 远程 / 休假排期：`text-sky-700 bg-sky-50 border-sky-200`
    - 警告 / 休息中 / 待审批：`text-amber-800 bg-amber-50 border-amber-200`
    - 危险 / 缺勤 / 病假 / 驳回：`text-rose-700 bg-rose-50 border-rose-200`
    - 中性 / 未开始 / 已归档：`text-slate-600 bg-slate-100 border-slate-200`
- **数字排版**：所有工时、时间、日期、薪资、人数、周次、统计数值**强制添加 `tabular-nums`**，保证纵向对齐。
- **无障碍对比度红线（WCAG AA）**：纯白底色上的所有可读说明文字、表单辅助文案与底部合规小字**最低使用 `text-slate-600`**（对比度 ≥ 4.5:1），严禁将 `text-slate-400` 用于需要用户阅读的正文/条款。
- **绝对禁止清单**：
  - 禁止暗黑背景主工作区、禁止浅蓝侧边栏、禁止任何紫蓝渐变/渐变背景/渐变文字/发光霓虹效果。
  - 禁止使用 Emoji 作为功能图标（统一使用 `lucide-react` 16px/20px 细线图标）。
  - 禁止重阴影与超过 1 层阴影嵌套（卡片仅限极柔 `shadow-[0_1px_2px_rgba(15,23,42,0.04)]`，Popovers/Drawers/Dialogs 仅限单层 `shadow-sm`/`shadow-md`）。
  - 禁止向界面透出任何原始后端英文异常或 JS 堆栈（所有异常必须走 `errorTranslator.ts` 与全局 `ErrorBoundary`）。

## 2. 五套标准页面母版骨架
所有核心页面必须严格归入以下 5 套标准母版之一：

1. **双视角企业首页 Dashboard（Personio 双栏 + 管理视角）**：
   - 顶部日期 + 时段问候语（`下午好，[姓名]` / `Buenas tardes, [Nombre]`）+ 管理员/员工视角切换开关（普通员工隐藏）。
   - **员工视角双栏**：左宽栏为待办与审批高亮卡（`Destacados`）、本周团队日程（`Esta semana`）、近期生日与入职周年（`Celebraciones`，头像带年份小徽章 + 一键祝贺）；右窄栏为**环形工时打卡卡（`Registro de jornada`）**（上方状态锁定按钮 + 2 个 SVG 环形进度条：已工作/已休息 + 下方当日分段明细 `Trabajo 08:00 → 14:00 · 6h`）与**个人快捷名片**（头像/职位 + 无截断三快捷入口 `打卡/请假/文档` + 独立大号剩余年假卡）。
   - **管理视角**：`Who's in` 6 状态实时头像墙（点击分类打开右侧明细抽屉）+ 近期节假日 + 近期生日/周年 + 待签收公告统计 + 快捷报表，卡片视觉完全统一。
2. **组织与员工花名册（`Organización`）**：
   - 顶部主 Tab：`员工列表 (Personal)` \| `组织架构 (Organigrama)`。
   - 高级工具栏：视图切换、IME 安全搜索框、带已选数量徽章的 `筛选 (Filtrar)` 按钮、总人数 `tabular-nums` 统计、右侧 `自定义显示列 (Columnas)` 与批量导入/导出菜单；下方展示可一键关闭的已选筛选胶囊（如 `部门: 门店A ×`）。
   - 高密度数据表：表头带极细微型图标，行内展示圆形头像 + 姓名 + 部门 + 邮箱 + 门店 + 岗位，点击整行进入员工 360° 档案页。
3. **团队日历与缺勤时间轴（`Gestión del tiempo`）**：
   - 顶部主 Tab：`团队日历 (Calendario del equipo)` \| `假期管理 (Ausencias)` \| `考勤记录 (Registro de jornada)`，右上角钴蓝主按钮 `+ 申请休假 (Solicitar ausencia)`。
   - 横向甘特图时间轴：左侧固定列（`sticky left-0 bg-white`）展示人数统计 + 员工头像/姓名/岗位；右侧按月份、ISO 周次（`S48 / S49`）、星期与日期横向平滑滚动，**企业钴蓝竖线高亮“今天”**，周末极浅灰底，各类请假/年假/病假用语义色条覆盖。
4. **员工 360° 个人档案页（`Perfil`）**：
   - 顶部富信息头图区：大号圆形头像（带编辑角标）、加粗姓名、语义状态胶囊（`在职 Activo`）、入职日期与司龄、汇报主管胶囊（带头像）；第二行带微图标展示岗位、部门、工作门店、所属公司实体。
   - 横向一级 Tab：`基本资料` \| `薪酬` \| `文档` \| `考勤记录` \| `假期`（本阶段不开发绩效/目标模块）。
   - 子页规范：**基本资料**为左侧垂直二级菜单（公开资料 / 人事信息 / 薪资社保信息 / 银行卡 / 紧急联系人）+ 右侧键值对视图与吸底 `修改 (Modificar)` 条；**文档**支持分类筛选、`+ 上传文档` 与 eSignature 签收状态列；**考勤记录**为顶部周切换器 + 并排双汇总卡（本周已录/应录工时 + 周一至周日标准排班明细）+ 每日明细表（含未来日期锁图标、`Progreso` 水平进度条、休息/请假与状态胶囊）。
5. **移动端一等公民体验（`390×844`）与通用空状态（Empty State）**：
   - 移动端采用深海夜蓝顶栏 + `#F3F5F9` 画布 + 纯白圆角卡片 + 企业钴蓝主色，保留底部固定导航（`首页 / 应用 / 我的`）与深海蓝悬浮打卡计时条（必须保留 `pb-36` 安全底边距防遮挡）。
   - 无数据/待配置区域统一使用简洁的 `EmptyState` 空状态卡片（细线图标 + 标题 + 简明引导语 + 可选操作按钮）。

## 3. 中西双语（`zh-CN` / `es-ES`）防爆版规范
- 西语长度常为中文的 2~3 倍：**严禁给按钮、Tab、快捷入口、表头写死固定窄宽度**，严禁出现 `Registro de jor...` 这类硬截断；必须留足宽度、合理换行或使用精炼西语短标签并辅以 `title` 提示。
- **窄屏 KPI 与卡片标题禁硬截断**：390px 移动端下严禁对 KPI 卡片标题使用 `truncate` 导致中西文截断；采用响应式 Grid（移动端标题 `col-span-2` 完整换行、`sm:` 恢复双列）。
- **用户输入分类归一化与筛选计数**：部门等自由输入字段用于筛选与分组时，统一通过共用 `trim().toLowerCase()` 归一化键归并（保留首次出现的展示大小写）；激活筛选或搜索时必须明确展示 `显示 X 位，共 Y 位`（`shown / total`），区分当前视图与总数。
- 所有日期、时间、货币、数字格式化必须使用原生 `Intl.DateTimeFormat` / `Intl.NumberFormat`（结合当前语言与门店 IANA 时区），严禁手工字符串拼接。

## 4. 交互与输入法防误触（联动 `modern-web-guidance`）
- **中文 IME 回车防误触**：任何监听 `Enter` 键执行搜索、提交、新建的输入框，**必须判断 `!e.nativeEvent.isComposing && e.keyCode !== 229`**，防止拼音选词误提交。
- **原生能力优先**：优先使用语义 HTML、原生 `<dialog>`/Popover、表单校验与清晰键盘焦点环（`focus-visible:ring-2 focus-visible:ring-blue-600`）。
- **React Effect 依赖稳定与“先读后写”防误覆盖**：
  - **严禁将 `= []` / `= {}` 默认新引用作为 `useEffect` / `useCallback` 依赖**（防止每次渲染重置表单输入）；依赖项收敛到原始 ID（如 `lockedEmployee?.id`）。
  - 任何可编辑配置表单与作用域工作区必须：① 在外层按 `tenant_id + role + scopeId` 设 `key` 隔离切换残留；② 用 `AbortController` 取消过期请求并忽略 `signal.aborted` 结果；③ 维护 `loading | ready | failed` 状态，**读取成功前禁止写入**，失败时提供中西双语重试按钮，杜绝用默认值覆盖线上配置；④ 保存/删除成功后通过 `onSaved` 修订号立即触发同页关联数据（如工时汇总表）刷新。

## 5. 公用平板打卡终端（Kiosk Mode）规范
- 打卡反馈展示完成后，**3 秒内必须自动清屏并重置全部本地状态**（清空员工姓名、工号、最近打卡结果与输入缓存），防止公用设备隐私泄露或下一位员工误操作。

## 6. 浏览器视觉与真交互验收规则（硬上限 ≤ 2 轮）
- 大改版或表单修复完成后，启动本地服务并使用 `chrome-devtools` MCP 在 `es-ES` 与 `zh-CN` 双语下实测桌面端（`1440×900`）与移动端（`390×844`）关键页面自检。
- **真交互闭环验收（禁止只截静态图）**：除确认无横向溢出、无标题截断、无控制台报错外，还必须：① **真实执行关键写操作并验证保存后同页刷新 + 重开弹窗回显**；② 核查白底可读小字对比度 ≥ 4.5:1；③ 动效页面验证 `prefers-reduced-motion` 生效。
- **最多允许 2 轮视觉修优循环**：发现截断、配色偏离、遮挡或控制台报错时原地修优并复测；达到第 2 轮上限必须停手并回报 Coordinator 审查，严禁无限调样式消耗 Token。
